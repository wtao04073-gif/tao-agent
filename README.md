# tao-agent

面向**高校服务机构**与**传统制造业**的通用 AI 办公 Agent 平台。以 [Pi](https://pi.dev/) 为 Agent 内核，支持 Docker 私有化部署与 SaaS 多租户两种形态。

## 这是什么

把 Claude Code 那种「能调工具、能派子 Agent、能异步执行长任务」的 Agent 能力，做成行业办公用户真正用得起来的形态：

- **场景卡替代空白输入框** —— 目标用户中能写出有效 prompt 的仅约两成，不能指望他们构思指令
- **机构知识资产沉淀** —— 记住本单位的模板、字段口径与历史修改意见，下次同类任务自动复用
- **原生 Office 交付物** —— 产出可直接编辑、盖章、流转的 docx / xlsx / pptx
- **数据不出门** —— 私有化部署满足高校数据分级与制造业图纸保密要求
- **执行中可继续对话** —— 任务与会话解耦，任务在跑时可以问别的

核心判断：这个品类的胜负手不是模型能力，而是**记忆与工作流嵌入**。多方独立调研显示企业 AI 试点大面积零回报，主因是「工具不学习、不记住、不贴合流程」——而非模型不行。

## 架构要点

Pi 是**极简 harness**——只有 `read`/`write`/`edit`/`bash` 四个工具，刻意不提供 subagent、MCP、权限系统、plan mode。它覆盖最内层的 Agent 运行时，其余全部自建：

```
入口层      桌面 Web / 移动 Web / 管理后台
网关层      身份与租户识别 · 事件下发 · 限流审计
平台服务层  场景 / 任务编排 / 知识资产 / 计量 / 租户权限 / 技能 / 产物 / 模型路由
执行层      Runner 池（一会话一进程）→ Agent Host（内嵌 Pi SDK）
            沙箱：SaaS=microVM · 私有化=容器+seccomp
数据层      PostgreSQL（行级安全）· Redis · 对象存储 · 向量检索
```

三条决定架构的硬约束（详见接口审计）：

1. **Pi 无法在单进程内承载多租户** —— 有 4 个进程级全局单例（含替换 `globalThis.fetch`、猴补 `process.stdout.write`）。隔离单元必须是操作系统进程。
2. **Pi 无任何执行隔离** —— 默认以启动它的用户权限运行，`bash` 无默认超时。沙箱是必须自建的第一等工程。
3. **Pi 的 session 存储不可替换且零并发保护** —— 会话状态的权威副本必须在自己的数据库里，Pi 的 JSONL 降级为运行时工作副本。

## 当前状态

需求已定稿，技术方案已完成，可交互原型已产出，Pi 内核已 vendor 进仓库（锁定 v0.87.1）。

[安全策略](docs/security-policy.md)已定稿，关键结论：

- **不允许** Agent 操作用户本机文件系统，改为「用户显式授权目录 + 沙箱内受控挂载」
- **不开放**自由 shell，所有能力封装为参数经校验的结构化工具（`bash` 默认不激活）
- 沙箱**保持全断网**，联网搜索经平台搜索代理出网，保住「数据不出门」
- 凭据路径硬编码黑名单，不留任何配置放开入口
- 审计日志采用追加写 + 哈希链防篡改，两形态默认开启

下一步是技术方案的 **M0 三个 spike**（并发隔离验证、检查点续跑、权限门与沙箱），三项通过才进 M1 最小闭环。
