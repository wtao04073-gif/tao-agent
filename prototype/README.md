# 行业通用 AI 办公 Agent 平台 — 可交互高保真原型

本目录是需求 Spec（仓库根目录 `README.md`）第 4 章「页面与交互」的可交互原型实现。
面向**高校服务机构**与**传统制造业办公管理岗**两类目标用户，用于需求评审、客户演示与前端开发交接。

- 技术栈：纯静态 HTML + CSS + 原生 JavaScript
- **零外部依赖**：不引任何 CDN、字体、图标库或图表库，双击即可离线打开
- 双主题：浅色 / 深色，默认跟随系统偏好，每页右上角可手动切换
- 演示数据存于浏览器 `localStorage`，桌面端与移动端共享同一份（体现「任务是与会话解耦的一等公民」）

---

## 1. 怎么打开预览

### 方式一：直接双击（最简单）

打开 `prototype/index.html` 即可。所有资源引用均为相对路径，`file://` 协议下可正常工作。

### 方式二：本地 HTTP 服务（推荐，行为最接近真实环境）

```bash
cd prototype
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000/
```

### 移动端页面的查看方式

`mobile/` 下的两个页面在宽屏浏览器中会自动渲染成 **375px 宽的设备框**，便于在桌面上演示。
若想看真实移动端效果，可用浏览器开发者工具的设备模拟（iPhone SE / 375×667）。

## 3. 每个页面演示了哪些关键交互

### 3.1 `desktop/workbench.html` — 场景工作台（Spec 4.2）

- **场景卡网格替代空白输入框**：12 张场景卡按「行业 → 职能」双层分组
  - 高校 5 个：生成审核评估自评报告 / 整理评估整改台账 / 多系统数据核对填报 / 起草校内通知公文 / 汇总科研项目申报材料
  - 制造 5 个：生成 8D 质量报告 / ISO9001·IATF16949 体系文件比对 / 供应商对账核查 / 设备台账整理 / 编制作业指导书 SOP
  - 通用 2 个：数据统计与图表 / 汇报材料成稿（PPT）
- **引导式要点收集**：点击场景卡弹出表单，字段随场景变化（文本 / 日期 / 数字 / 下拉 / 多选 / 附件）
- **必填校验真实拦截**：未填完时禁止提交，顶部汇总「缺哪几项」，字段级红框与错误文案，焦点自动落到第一个未通过项
  - 加严规则示例：声明「至少 2 份」的附件字段，只传 1 份也会被拦并说明原因
- **租户自建覆盖平台预置**：「多系统数据核对填报」「供应商对账核查」标记为「本单位自建」
- **自由对话入口存在但不突出**：虚线弱化样式，置于场景网格下方
- **状态完备**：首次进入空态引导（推荐 3 个最快见效场景，可关闭）、搜索无匹配时引导自由对话、最近产出为空时的空态
- 行业筛选器与关键词搜索真实过滤；全局「进行中任务」提示条常驻

### 3.2 `desktop/session.html` — 会话执行页 ★ 核心（Spec 4.3）

这是本原型最重要的页面，演示 Spec 中最关键的产品主张：

- **★ 任务执行中可继续对话（对应 Pi 的 steering 语义）**
  - `setInterval` 每 3.2 秒推进一步，逐步点亮步骤、更新「正在做第 N 步：具体动作」
  - **输入框在任务执行期间始终可用、不禁用、不置灰**
  - 用户发送的消息立即上屏，但标记为「**已插入，将在当前步骤完成后送达**」（黄色虚线气泡 + 脉冲点）
  - 到下一个步骤边界时，排队消息转为已送达状态（「已在步骤边界送达，原任务未中断」），并给出贴合业务的回应
  - 输入区提示文案随状态变化：`输入框始终可用` → `任务执行中，你仍可输入` → `N 条追问排队中`
- **步骤级进度可见，而非转圈 loading**：每个场景有专属执行计划，动作描述具体到「核对供应商对账明细，定位金额与数量差异」
- **中间产出物**：第 3 步起显示「已产出中间物」（任务失败也保留）
- **产出物卡片是原生 Office 文件**：`.docx` / `.xlsx` / `.pptx` 彩色角标 + 真实业务文件名，操作含预览 / 下载 / 继续修改 / 提出修改意见
  - 预览按格式分别渲染：docx 渲染成公文版式、xlsx 渲染成保留 `=SUM` 公式的表格、pptx 渲染成页面缩略图网格
- **引用来源标注**：AI 产出文末带数字角标，点击展开引用了哪份知识库文档、第几节、原文片段，并说明「检索强制携带租户与权限过滤」
- **修改意见回写**：提交后明确提示「**已记录，下次同类任务将自动应用**」，说明写入哪一级口径资产并生成版本号；数据同步到知识资产页
- **高危动作确认**：选「生成 8D 质量报告」跑到第 5 步弹出确认卡片（对外发送邮件），可确认 / 跳过，确认后记入审计
- **失败态**：选「多系统数据核对填报」固定走失败分支，显示可读失败原因（合并单元格导致表头无法定位）+ 保留中间物 + 「从检查点重试」按钮，重试时说明「前序步骤不重复消耗」
- **排队态**：并发满时进入排队，7 秒后模拟前序任务释放并自动开跑（期间输入框依然可用）
- **任务与会话分离**：页内顶部仍有全局「进行中任务」提示条，右侧栏列出「本会话其他进行中任务」
- 右侧栏还展示：本次生效的知识资产（含已应用的回写意见数）、以产物与任务为单位的用量、模型分层路由与缓存命中率

### 3.3 `desktop/tasks.html` — 任务中心（Spec 4.4）

- **状态筛选真实过滤**：全部 / 执行中 / 排队中 / 等待确认 / 已完成 / 失败 / 已取消
- 场景筛选、三种排序（最近更新 / 创建倒序 / 按状态分组）、标题与任务号搜索
- **取消 / 重试真实改变行状态**并回写共享数据（会话页与移动端同步可见）
  - 重试按「从检查点第 N 步续跑」处理，提示已完成步骤不重复消耗模型调用
- **批量操作**：勾选多行后「重试所选 / 取消所选」，按钮按可操作数量动态启用
- **任务详情**三标签页：执行日志（带级别标签）/ 产物（区分已就绪·中间物·草稿）/ 消耗（tokens、成本、沙箱时长、以产物与任务计的额度）
- **失败原因归类**：数据源格式问题 / 执行超限 / 权限不足 / 额度不足 / 其他
- **并发占用提示与升档引导**：达上限时橙色提示条 + 「查看升档方案」直达管理后台配额区
- **两种空态**：完全无任务（引导去工作台）/ 筛选后无结果（一键清除筛选）

### 3.4 `desktop/knowledge.html` — 知识资产（Spec 4.5）

- **文档上传的状态流转**：点击演示按钮 → 进入解析队列 → 「解析中 N%」带进度条 → 「已就绪」并显示切片数与被引用次数
  - 另提供一个必然失败的上传项，演示「解析失败 + 可读原因（扫描件无文字层，建议先 OCR）+ 重新解析」
- **权限读写分离的 UI 体现**：权限矩阵表（角色 × 查看 / 检索引用 / 上传 / 编辑 / 删除），普通成员默认只有前两项
  - 只读库中点「删除」会被拒绝并提示「你只有查看与检索引用权限」
- **权限不足提示区分两种情况**：完全不可见（红色，检索也不会召回）vs 可见但不可编辑（橙色）
- **四级资产范围**：平台通用 / 租户共享 / 工作区专属 / 个人私有，可在权限弹窗切换
- **模板库**：标出同名模板被高优先级覆盖（如平台版自评报告模板被租户版覆盖）
- **字段口径定义表**：真实业务口径（师生比折合算法、不良品率 PPM、FTT、对账容差），标注哪些来自修改意见回写
- **修改意见回写**：4 条历史意见 + 会自动合并你在会话页刚提交的意见（标「本次会话新增」）；空态有引导
- **版本与变更记录**：可回溯谁在什么时候改了什么、版本号变化、生效范围
- 7 个知识库覆盖：正常可写 / 只读 / 个人私有 / 无权访问（🔒）/ 空库；支持新建

### 3.5 `desktop/admin.html` — 管理后台（Spec 4.6）

- **用量与产出看板（纯 CSS / SVG 绘图，不引图表库）**
  - 交付物产出趋势：纯 CSS 堆叠柱状图，按 docx / xlsx / pptx 三色分层，6 个月
  - 席位周活率：内联 SVG 折线图 + 面积填充 + 40% 目标虚线 + 数据点标注
  - 场景采纳排行、成员使用分布：CSS 横向条形图
  - 6 个关键指标块对齐 Spec 第 1 章成功指标（首周产出率、周活率、格式保真率、人均成本等）
- **成员与角色表**：角色下拉可直接修改，即时生效并写入审计日志；状态区分正常 / 低活跃 / 未使用 / 已熔断
  - **单用户级熔断**：显示已熔断成员，可一键解除
  - 未使用成员可「发送使用提醒」（呼应「上级明确要求使用是最强采纳杠杆」）
- **技能包管理**：三级命名空间（平台共享 / 租户私有 / 会话临时）可视化，启停即时生效并写审计，会话临时技能显示剩余生存期
- **场景卡管理**：列出全部场景，标出「覆盖同名平台场景」的租户自建项
- **模型与路由**：分层路由配置（旗舰档用于规划裁决、轻量档用于常规执行）、上下文缓存开关、「保存并热生效」说明无需重新部署
  - **回归评测门禁**：可点击运行，7 条覆盖两个行业核心场景的用例集逐条通过后放行
- **配额与并发**：当前档位、用量预警、升档对比与申请
- **审计日志**：可检索；覆盖高危动作确认、权限变更、越权拒绝、配额熔断、技能变更、模型配置；本页操作会实时追加新记录

### 3.6 `mobile/tasks.html` + `mobile/session.html` — 移动端 Web（Spec 4.7）

- 375px 宽度适配，触摸目标 ≥ 40px，筛选条可横向滚动
- 与桌面端**共享同一份任务数据**：桌面端跑的任务，移动端刷新即可见
- 任务完成通知条 + 产物「可取回」标记
- 会话页进度压缩为「当前动作 + 进度条 + 可展开的完整步骤列表」
- **执行中同样可追问**，排队送达语义与桌面端一致
- 产物取回 / 复制分享链接 / 转发；高危动作确认与失败重试在移动端也能完成
- **不支持的复杂操作明确引导至桌面端**：发起复杂任务、管理后台、在线编辑、口径回写范围选择

## 4. 建议的演示路径

### 主链路（约 3 分钟，走通 Spec 4.1 核心旅程）

1. 打开 `index.html` → 点「场景工作台」
2. 点「**供应商对账核查**」场景卡
3. **什么都不填，直接点「提交执行」** → 观察必填校验拦截，顶部列出缺的 4 项
4. 补齐：对账期间填「2026年9月」→ 用「+ 文件名」按钮带入 3 份附件 → 容差填 50 → 勾选差异归类维度
5. 点「提交执行」→ 自动跳转会话执行页，任务开始分步推进
6. **★ 任务执行中直接在输入框输入**「差异原因也要写清楚，按供应商归类」并发送
   → 消息显示「**已插入，将在当前步骤完成后送达**」，任务不中断
   → 下一个步骤边界，消息转为已送达并得到回应
7. 再输入一句「这个大概还要多久」→ 同样排队送达，得到进度回答
8. 步骤跑完 → 出现 `供应商对账差异明细表.xlsx` 产出物卡片
9. 点「预览」→ 看到保留 `=SUM` 公式与会计格式的差异明细表
10. 点「**提出修改意见**」→ 选「格式与版式问题」、范围选「本工作区」、填写意见 → 提交
    → 提示「**已记录，下次同类任务将自动应用**」
11. 进「知识资产」→ 切到「修改意见回写」标签 → 看到刚提交的意见已沉淀（标「本次会话新增」）

## 5. 设计系统说明

集中定义在 `assets/style.css` 顶部的 CSS 变量中，改这一处即可全局换肤。

- **配色**：沉稳靛蓝为品牌色（适配政企与制造业审美），语义色分 ok / warn / err / info / run 五组，每组含背景 / 前景 / 描边三个层级以保证两种主题下的对比度
- **双主题**：`[data-theme="dark"]` 手动覆盖 + `@media (prefers-color-scheme: dark)` 跟随系统；选择记在 `localStorage`
- **字体**：`"PingFang SC", "Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", ...` 中文字体栈优先
- **间距**：4px 基准的 `--sp-1` ~ `--sp-10`
- **行业色带**：高校（蓝）/ 制造业（橙）/ 通用（灰），在场景卡与任务列表中一致使用
- **Office 文件图标**：用各 Office 应用的品牌色块 + 字母（W / X / P），强调「产出是原生 Office 文件而非 Markdown」
- **图标**：全部为内联 SVG 或 emoji，无图标库
- **可访问性**：统一 `:focus-visible` 焦点环、语义化标签（`nav` / `main` / `table` / `dl`）、`aria-current` / `aria-pressed` / `aria-selected` / `aria-invalid` / `role="progressbar"` / `aria-live`、跳转主内容链接、`prefers-reduced-motion` 下关闭动画
- **响应式**：桌面 ≥ 860px 为固定侧边导航 + 主内容区；< 860px 侧边导航降级为顶部横排；移动端页面 375px 基准，宽屏下渲染为设备框便于演示
- **打印样式**：隐藏导航与输入区，便于把原型页面贴进评审材料

## 6. 取舍与未实现项（诚实说明）

原型定位是**交互与信息架构验证**，不是功能实现。以下内容有意做了简化或未实现：

### 刻意简化（用前端模拟代替真实能力）

1. **Agent 执行是脚本化模拟**：`setInterval` 按预设步骤脚本推进，步骤文案与时长都是写死的，没有真实模型调用、工具调用或 Agent Loop。
2. **文件上传是模拟**：没有真实文件选择器与上传，改为「+ 文件名」按钮一键带入预设文件名；解析进度是定时器递增。
3. **产出物不是真实文件**：预览是用 HTML 还原 docx / xlsx / pptx 的视觉效果，「下载」只弹提示，不产生真实文件。**因此「Office 与 WPS 打开校验」「表格保留公式」只能在 UI 层表达，无法真实验证。**
4. **数据存储用 localStorage**：没有后端与数据库，也就没有真正的多租户行级隔离——租户隔离、跨租户不召回只在文案与 UI 层表达。
5. **登录与身份是固定的**：默认以「刘敏（工作区管理员）」身份进入，工作区切换器只切换显示文案与提示，不真的切换数据范围。
6. **AI 回复是规则匹配**：追问的回应用正则关键词匹配挑选预写文案，不是真实生成。
7. **引用来源是预设的**：每个行业一组固定引用片段，不随实际内容变化。

### 未实现的 Spec 内容

1. **子 Agent 并行的过程可视化**：Spec 3.2 提到主 Agent 派发并行子 Agent。原型只在自评报告场景的第 4 步文案里写了「6 个一级指标并行，上下文隔离」，**没有做并行子任务的树状展开视图**。这块 UI 形态需求本身在 Spec 里也未细化，建议后续单独设计。
2. **树状可分叉会话历史**：Spec 第 7 章提到 Pi 提供「可回到任意历史点分叉」以支撑「同一材料试多个版本」。原型的会话是线性流，**没有做分叉与版本对比 UI**。
3. **定时任务与主动服务**：Spec 3.7 / 分期建议三期内容，原型未做入口。
4. **部署与交付相关界面**：Spec 3.11 的环境自检、安装自检、自助排障知识库属于交付工程侧，原型未涉及。
5. **知识库文档的切片级查看**：点「查看切片」只弹 Toast 显示切片数与被引用次数，没有做片段浏览与命中高亮。
6. **模板套版的可视化编辑**：模板库只有列表与版本，没有模板字段映射或预览编辑界面。
7. **移动端任务完成的系统级推送**：只做了页内通知条，没有 Web Push 或 PWA 能力。
8. **对比两次产出验证回写生效**：Spec 验收标准提到「可通过对比两次产出验证」修改意见生效。原型只在文案与知识资产页体现意见已沉淀，**没有做两次产出的 diff 对比视图**。

### 一处有意的产品化补充（Spec 未明确要求）

- 任务中心的**失败原因归类**（数据源格式问题 / 执行超限 / 权限不足 / 额度不足）：Spec 4.4 只说「失败任务的原因归类展示」，具体分类维度由原型提出，需产品确认。
- 管理后台对「未使用成员」提供**发送使用提醒**入口：源自 Spec 4.6 注释中「上级明确要求使用是最强采纳杠杆」的推论，属于原型主动补充的采纳机制，需产品确认是否保留。
