## 包划分与依赖方向

```
@tao/core ──────────────┬─→ @tao/office        （Excel 核对与产出）
  共享词汇表             ├─→ @tao/orchestrator  （任务状态机与事件流）
  零运行时依赖           └─→ @tao/agent-host    （唯一接触 vendor/pi 的包）
                                  │
                                  └─→ vendor/pi （Pi 内核）
```

**关键纪律：只有 `agent-host` 可以 import vendor。** 由 `npm run check:boundaries` 守卫 —— 靠人自觉必然失守，一次赶工的 import 就会把内核类型泄漏到全平台。该检查已反向验证能抓到包名式与相对路径式两种越界形态。

这条纪律决定了「将来能否换掉内核而不动业务代码」，也就是[自主可控](../vendor/pi/README.md)的完整含义。

## M0 约束在代码中的落点

三条来自[技术验证](../spikes/README.md)的硬约束，都已从文档承诺变成代码事实：

| 约束 | 落点 |
|---|---|
| 必须显式传 `streamFn` | `InProcessRunnerFactory` 经 `models`/`model` 注入，从不省略 —— 省略会落到内核的进程级全局 `defaultStreamFn`，多会话共用同一模型入口 |
| 一人一 Session | 每个 Runner 独占一个会话存储。同 Session 的多 lane 在 mutation line 上串行，共用会让用户互相排队 |
| 权限门 fail-closed | 刻意**不** try/catch —— 内核在 `before_tool` 抛异常时拒绝执行，自己兜底反而可能把拒绝变成放行 |

## 产品口径上必须准确的一处

**「执行中可继续对话」不等于「打断」。** 内核 steering 的消息落在当前 assistant turn 及其全部工具调用完成之后，**永不取消执行中的工具**（只有 `abort()` 能）。

因此事件里的投递语义固定为 `queued_after_current_step`，前端文案必须是「已插入，将在当前步骤完成后送达」。承诺「立即打断」是无法兑现的。

## 实现过程中修掉的两个真实缺陷

这两个都是**测试先抓到的**，不是事后发现：

### 1. 容差判断自身受浮点误差影响

`100 - 100.01` 得出 `-0.010000000000005116`，绝对值略大于 `0.01`，于是「差额恰为一分钱、容差一分钱」被判成差异。用户设了容差却仍被报出边界差异，会直接怀疑工具不准。

根因：**误差量级取决于相减的操作数（100），而非相减的结果（0.01）。** 按结果量级算出的 epsilon 小两个数量级。已补 7 组边界断言，并单独验证容差既不过严（浮点误差不误报）也不过宽（1e9 量级下真实差异仍报出）。

### 2. 根 vitest 配置被 vendor 包意外继承

新建仓库根 `vitest.config.ts` 后，`telemetry` 与 `chord`（上游无自有配置）向上继承了它，报 `No test files found`。这是**我们引入的环境副作用**，已按纪律登记为 [P001](../vendor/pi/PATCHES.md)。

## 测试策略

| 层 | 方式 | 为什么 |
|---|---|---|
| 纯逻辑（对账、状态机、路径策略） | 穷举 + 真实脏数据形态 | 对账正确性是产品价值核心，客户拿它过验厂审核 |
| 适配层 | **真实内核**（假模型，离线） | 适配层有 `as never` 断言绕过内核类型，编译通过不代表运行时正确 |
| 权限门 | 单元 + **真实内核集成** | 单元测试证明策略正确，但接线出错时它依然全绿而实际防护为零 |
| Office 产物 | **真实 xlsx 文件往返** | mock 掉文件层恰好会把公式退化、格式丢失全部隐藏 |
| 端到端 | 真实文件 + 真实内核 + 真实产出 | 只有模型是假的 —— 模型输出的随机性会让断言无法稳定 |

**安全代码按攻击性方式测**：不是验证「正常路径能通过」，而是穷举绕过手法（`../` 穿越、大小写变形、授权目录前缀混淆 `/mnt/share` 与 `/mnt/share-evil`）。

**关键断言做变异测试**：把实现改坏，确认对应用例精确失败。已验证 4 处 —— 权限门放行、fail-closed、状态机守卫、授权目录朴素 `startsWith`。未经反向验证的断言可能只是装饰。

## 一期的能力边界（诚实记录）

- **产物校验**只能验证文件结构合法、可重新打开、公式与格式未退化；**不能**验证「在 WPS 里肉眼看着对不对」—— 那需要真实 Office 环境，属交付前人工抽检
- **任务编排是进程内实现**，适合单机 Compose 私有化部署。分布式调度、并发配额、租约留到 M2，但状态机与事件流契约现在就定下来了，因为它们跨形态共用
- **表头按标准格式处理**（第一行为表头）。合并标题行等异常格式会给出可读报错，而非静默产出错误结果
