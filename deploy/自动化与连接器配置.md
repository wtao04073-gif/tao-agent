# 自动化与连接器配置

自动化、机器人凭据、OIDC配置与授权事务均使用AES-256-GCM整条加密，只有记录编号和租户索引保留明文且受认证保护。独立的 `.automation-store.key` 以0600权限保存在持久根目录，必须与数据协调备份、分权保管；密钥丢失或不匹配时拒绝读取，不能生成新密钥覆盖。旧明文记录在读取时原子迁移到密文。此文件密钥模式不等同于外部KMS，应由部署方进一步限制持久卷与备份访问。

## 部署与恢复

调度器与主 HTTP 服务同进程运行，关闭网页不影响计划。`AutomationManager.start()` 启动一秒轮询，关停调用 `stop()`。数据目录必须使用持久卷，并与任务存储和 ExecutionRegistry 一同备份恢复。文件存储只支持单实例；不能将相同目录挂载给多个同时运行的副本，也不提供分布式锁或高可用承诺。

每次发生项先保存，再通过原有任务提交回调传固定 `automation:<发生项摘要>` 幂等键。重启后可恢复待提交项和回读 registry 已提交结果；提交结果不确定时停留在“待核对”，不能擅自换幂等键重放。任务本体重启后的状态沿用原有任务系统，`INTERRUPTED` 显示失败记录，人工从任务页决定后续动作。

停机漏发采取合并策略：只补跑最早漏掉的一次，然后跳到当前时间之后，避免大量突发任务。Cron 支持五段表达式与 IANA 时区；间隔最短60秒。暂停影响后续发生项，已经提交的任务须单独取消。删除计划保留历史。历史面板返回最多200项，落盘记录不自动删除；运维须监控数据目录空间，长期高吞吐场景应迁移到共享数据库与队列后再扩容。

## 第三方鉴权与错误

[openapi.json](openapi.json) 定义管理与入站接口。管理请求使用现有部署授权的 Bearer 凭据，或 `tao_session` 会话；Cookie 修改请求必须携带宿主提供的 `X-CSRF-Token`。凭据不应放入 URL、浏览器存储或交付文件。自动化及绑定按租户、工作区和创建账号共同隔离。

自动化管理按身份限流120次/分钟；入站按连接器60次/分钟、真实 socket 地址120次/分钟。429返回 `Retry-After: 60`。自动化错误体包含 `error` 和 `code`；历史中的“待核对”是持久提交存在不确定结果，不能作为普通网络失败自动重试任务。

## 签名 Webhook

登录工作台创建连接器，填写发送端 `senderId` 与至少32字符的独立随机签名密钥。创建后的回调路径是 `/api/connectors/inbound/{id}`，`{id}` 使用该连接器返回值。示例请求体：

```json
{"eventId":"sender-event-001","senderId":"external-user-id","text":"根据已授权资料整理日报"}
```

请求头 `X-Tao-Timestamp` 为 Unix 秒数，`X-Tao-Signature` 为 `HMAC-SHA256(secret, timestamp + "." + 原始UTF8请求体)` 的小写十六进制。服务允许正负300秒时差。代理不能改写请求正文。相同连接器内 `eventId` 持久去重；重试必须保留同一事件编号。请求体最大64KB，任务文本最大16000字符。外部传入的租户、角色或工作区字段均不能改变服务端身份。

## 飞书与企业微信

飞书应用机器人填写 `verificationToken`、`encryptKey`，将发送者 `open_id` 显式绑定到当前内部账号。入口校验时间戳、nonce与原始正文SHA256签名，支持AES-CBC加密信封、challenge和 `im.message.receive_v1` 文本消息事件，随后核验token和发送人。应用权限、订阅事件、平台发布仍须在飞书开放平台配置。

企业微信使用企业自建应用的消息回调，填写 Token、43位 EncodingAESKey、CorpID，绑定成员 UserID。入口支持 GET 加密回调验证及 POST 文本消息，校验SHA1签名、AES-CBC填充、消息长度、CorpID与发送人；MsgId去重。它不把只能发送的群机器人Webhook伪装成入站机器人。

凭据为空时状态是“未配置”并拒绝事件。“已配置”只表示配置字段齐备；实际云平台接通必须由管理员完成平台验证。当前自动化测试使用协议构造消息，不能替代真实应用验收。

## 原生IM结果私聊

飞书连接器可额外填写 `credentials.appId` 与 `credentials.appSecret`；企微连接器可额外填写 `credentials.corpSecret` 与 `credentials.agentId`（沿用已配置的CorpID）。完整填写后，结果优先通过平台原生消息API发送给该连接器固定绑定的 `externalUserId`，不使用generic webhook冒充消息接口。禁止 `@all`、竖线或多个收件人，任务正文无法改变收件人。未填写原生凭据的旧配置继续支持原有显式generic webhook结果回调。

飞书使用 `tenant_access_token/internal` 获取应用令牌，再调用 `im/v1/messages` 并固定 `receive_id_type=open_id`。企微使用 `gettoken` 和 `message/send`，固定 `touser` 与应用 `agentid`，不设置部门、标签或群发目标。凭据及原生投递快照均加密保存；访问令牌仅缓存于服务端内存，到期或遇到平台明确失效响应时刷新。配置查询中 `nativeDeliveryStatus=configured` 只表示字段完整，不代表已完成真实平台发送验收。

回发内容包括任务状态、任务编号、最终文本与产物名称；超出平台文本大小上限时保留摘要并提示到工作台查看完整结果。飞书使用稳定的uuid，企微启用平台重复消息检查；已成功投递的记录不会自动重发。明确的429/5xx进入持久重试队列，可取消或手动重试。如果消息请求已发出但响应中断，或者进程在发送中退出，记录将显示结果不确定并停止自动重发，需先在接收端核对后手动决定，以避免重复通知。

## 结果投递

计划或连接器可配置HTTPS标准443端口的回调与独立签名密钥。默认安全出网会阻断私网、元数据地址及重定向，并将DNS解析结果固定到连接，防止DNS重绑定。投递内容包含固定 `eventId`、任务编号和最终状态；主集成提供 `getResult` 时附带最多32000字符最终文本和最多100个产物名称，不附带内部路径或完整运行事件。

签名使用相同的 `X-Tao-Timestamp` 与 `X-Tao-Signature` 规则，另带 `X-Tao-Event-Id`。接收方须按eventId去重：网络中断或进程在成功响应后中断，可能再次投递同一个结果。单次超时10秒，429及5xx自动重试，最多5次；遵守Retry-After并设一天上限，其余非2xx直接失败。可在面板取消或手动重投；取消不能撤回接收方已经收到的数据。

办公MCP目录只提供配置入口和安装步骤；实际服务安装、连通探测与工具授权继续使用原有MCP管理。专家目录提供少量可直接创建的模板，不将模板数量标为市场覆盖率。
